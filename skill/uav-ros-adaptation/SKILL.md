# ROS 接口与版本适配

## 选择方案

平台数据源选择、传感器扫描模型和物理测量语义适配由 [平台传感器适配](../uav-platform-sensor-adaptation/SKILL.md) 负责；本 Skill 聚焦 ROS 版本与传输实现，并确保这些已定义语义在迁移中不丢失。仅涉及 ROS 发行版迁移时，无需额外进行平台传感器改造。

读取项目约定，确认算法和 AS2 的实际 ROS 发行版、操作系统、消息版本和输入输出。区分 ROS 1→ROS 2 与 ROS 2 发行版差异，不默认都需要桥接。

ROS 2 发行版之间可比较 remapping、独立 Adapter 与源码修改；ROS 1→ROS 2 则必须迁移构建系统、消息、节点、参数、时间、QoS 和启动入口，使算法进程本身在 Humble 运行。ROS 1 容器、`ros1_bridge`、专用 Proxy 或自建 TCP/Unix socket 桥只能用于离线数值基线，不能作为 PC 复现、板端支持或交付方案。迁移不得只处理输出：真实 ROS 2 传感器输入、算法核心和全部活动输出必须处于同一 ROS 2 运行链。

## 必查契约

| 方面 | 检查与处理 |
| --- | --- |
| 字段 | 检查实际赋值代码与运行样本；消息类型相同不代表字段已填。说明缺失值、单位、协方差含义与有效性 |
| 时间 | 区分采样、积分终点、估计时刻、发布与接收时间；核对时钟域、延迟、偏移、回放 `/clock` 和 reset。不得通过改为 now 掩盖时延 |
| 空间 | 明确 ENU/NED、FLU/FRD、父子帧和旋转方向；说明外参 T_A_B 的方向与标定来源。改 frame_id 不能代替数值变换 |
| 速度 | 确认表达坐标系和参考点；从 IMU 原点转机体原点时检查角速度与杆臂项 |
| 传感器 | 检查 IMU 测量来源、点云字段和逐点时间、扫描格式、图像编码、内外参、畸变与同步；示例标定不是实机标定 |
| 传输 | 检查自定义消息、QoS、队列、数据率、包大小、断连与重连；状态避免重连后重放过期缓存，地图/录包是否允许丢帧另行声明 |
| 发布权 | 命名空间、TF、时钟来源和权威状态源唯一性；桥不擅自替代原有发布者 |

状态输出还要区分“优化结果”和“实时传播状态”。先从官方 launch、下游订阅代码和运行频率确认每个 topic 的用途：关键帧或后端优化输出可以低频且不均匀，高频 IMU 传播输出才可能满足控制 freshness。两者即使都使用 `nav_msgs/Odometry` 也不能互换。Adapter 应选择与目标用途一致的正式状态流，并在命名和文档中保留其时间语义；不能用放宽 freshness 门槛掩盖选错 topic。

## 实现与检查

ROS 骨架调用独立 HTTP 模型 worker 时，ROS 接口仍保留观测时间和 frame；HTTP 仅为内部实现，不作为替代 ROS 的对外能力入口。深度 `32FC1` 米与 `16UC1` 毫米需处理行 stride、端序和无效像素；模型 worker 不负责隐式 TF 或时间同步。返回结果保留输入状态 header 和请求标识。HTTP 超时不等于计算已取消，worker 在实际计算完成前保持忙，避免仅凭客户端超时就释放执行槽。

用必要的非恒等坐标样例、已知角速度和杆臂验证变换，检查时间戳保留、无效值与陈旧输入、桥断连恢复、点云二进制布局。测试应覆盖实际消息链路，不只调用转换函数。校准和输入缺失时报告条件，不虚构参数或精度。

上游实时 wrapper 不是可信契约来源：逐项检查它是否用输入采样时间、是否填写速度、跟踪失败时是否仍发布，以及 ROS 2 消息对象能否被核心读取。若核心可直接消费 PointCloud2 数据布局，优先编写原生 ROS 2 Adapter 而不是为 ROS 1 wrapper 建桥。上游只输出离散 pose 时，可在 Adapter 用相邻有效样本和真实采样间隔计算明确表达坐标系的有限差分 twist；首个样本没有速度依据时不发布完整状态，不能填零伪装就绪。跟踪丢失、处理异常、重置或全局回环修正会破坏相邻样本连续性，必须重置有限差分基线并等到新的连续样本，不能把位姿跳变伪装成速度；仍不得宣称全局修正输出同时是平滑局部 odometry。

对 XYZ-only 仿真点云，先核对算法选用的具体预处理器：ring、逐点时间或强度缺失时，不以补零和 PCL 转换成功作为兼容证据。某些驱动处理器会在时间缺失时按扫描角速度推算；必须核实仿真扫描方式、顺序和时间单位是否符合该模型。瞬时整帧数据与旋转扫描数据应明确区分，必要时适配预处理入口或传感器输出，并用运动场景验证；不得伪造测量时间或把合成测试配置直接作为真实传感器配置。

固定 PX4 与 onboard 镜像出现消息载荷长度不一致时，先逐类核对固件生成的消息定义、镜像内 `px4_msgs` 和实际报错话题。若控制链消息已兼容、只有额外诊断消息版本落后，可从仓库锁定的 `px4_msgs` 生成外部 overlay，并在所有订阅该诊断话题的参与者中显式优先 source；这不需要替换镜像内 PX4，也不构成重建共享镜像。必须记录固件 schema、overlay 提交和受影响话题，并重新验证控制链与诊断解码；不得用一个话题通过推断整套消息版本兼容。

PointCloud2 兼容还要检查解析器的运行依赖而不只看消息字段。例如解析模块可能在类型常量处依赖 `rosbags`，即使实际传入的是 `sensor_msgs/msg/PointCloud2`；这类隐式导入须进入锁文件并通过镜像内导入测试。

交付版本兼容方案、方向明确的接口表、适配代码/配置、可重放测试及限制。端到端功能与故障恢复验收由验证流程完成。过程记录进入 `skill/temp/<任务>/`，日志进入 `log/`，收尾回馈已有 Skill。

## 已有案例

FAST-LIVO2 的 ROS 2 锁定实现通过专用 Adapter 规范帧、时间、QoS、瞬时 LiDAR 和重复点云，再由原生 AS2 插件接入，不能仅 remap 到 raw_odometry。算法世界坐标必须转换到平台控制所使用的 canonical `odom`；若点云需要保留算法原生世界，则通过带实际旋转/平移的静态 TF 关联，不能发布恒等别名。该结论来自特定版本，接入其他版本仍须重新核查。

## 目标消息与参数的实际兼容性

从运行中的发布端或其锁定构建确定消息定义、话题版本和类型支持，再核对接收端实际加载的包；不要仅凭话题名相同或接口可导入判兼容。需要改用另一话题时，逐项核对所需字段、单位、状态枚举、发布条件和新鲜度，不能为绕过版本冲突而丢失必要反馈。优先补编译匹配接口或实现有明确映射的适配，记录未覆盖字段与方向。验证产出包括两端定义来源、包/镜像身份、真实消息解码和消费者读取结果。

## 跨目标 Python 接口检查

可选数组先核对目标参数声明及YAML解析规则；空数组不能推断出所需类型时，按接口约定省略可选参数或显式声明类型，并检查实际节点解析后的参数。不要补入虚构元素来使解析通过。分别验证未设置、空值和有效值的真实入口，语法检查不能替代节点构造。

ROS 参数测试须包含 `Parameter.to_parameter_msg()` / `from_parameter_msg()` 往返，
或实际服务调用；DOUBLE_ARRAY 在目标 rclpy 可能返回 `array.array`。按 ROS 参数
类型及长度/有限性校验，不用 Python list/tuple 白名单误拒绝线上请求。运行期
目标变更须同时更新节点缓存，并限定执行已停止/静默状态。

固定长度ROS浮点数组在生成的Python类型中可能暴露NumPy标量；转JSON前逐值转换为原生float，并校验长度和有限性。用真实生成消息经过Adapter的服务调用验证，纯Python列表样例不能检出该差异。DiffPhys首次DDS调用曾因此在json.dumps处异常退出，修复后同一真实链路通过。

高分辨率Image出现延迟时分别测量RPC、字段赋值、DDS接收和模型耗时。
Humble生成的uint8数组setter可能逐元素校验bytes；可传入相同内容的
`array.array('B', payload)`走类型匹配路径，并验证序列化字节一致。
本项目镜像中1.23MB图像赋值曾测得bytes约50ms、typed array约0.8ms；
这是字段赋值证据，不代表整个相机或闭环已达到实时要求。

大图漏帧诊断用原采集stamp逐帧连接源发布和消费者接收记录。单看已收到帧的低年龄
会漏掉连续丢失的图像；只从接收端测得的时间间隔不能称作源采集停顿。
Humble DiffPhys 1.23MB深度图曾在BEST_EFFORT下出现源端约15Hz但消费者连续漏帧；
显式RELIABLE、KEEP_LAST=1后地面60秒927帧全部匹配。此为该部署的传输证据，
不是所有传感器改可靠QoS的依据；仍核查重传长尾和采集时间的新鲜度。
推理延迟分开记录请求发出、服务接收、HTTP开始/结束、服务响应就绪与客户端完成，
避免把GPU耗时、DDS延迟、客户端轮询和策略输出拒绝混为同一类故障。

固定共享镜像的 rclpy 可能没有便利客户端模块。先检查实际导入，必要时直接使用
标准 `rcl_interfaces/srv/SetParametersAtomically`，等待响应成功后再运动；不能因
便利 API 缺失就替换共享镜像。类型支持加载和无运动构造通过仍不等于跨机连通。

## 测量时间与未来参考时间

参考规划接口分别携带图像采集、实际定位观测及规划参考起点时间。仅参考起点允许有界未来；实际测量仍拒绝未来/陈旧输入，响应保留请求ID与两个时间头。目标世代变化或计算过期时丢弃响应，保持真实未结束请求占用，避免客户端超时造成请求叠加。对采样时间先在 ROS Duration 的纳秒网格生成唯一递增值，再构造曲线；`5.000000000000001` 与 `5.0` 会序列化成同一时间，导致执行端正确拒绝。保留该浮点边界回归，检查量化后的严格递增性。

使用目标 rclpy 和实际 TF 传输验证先消息、后TF的顺序；lookup_transform瞬时失败不能直接丢弃持续输入。请求已冻结快照后，新的图像暂时缺匹配状态不应使旧请求失效；响应检查冻结快照本身的年龄、任务世代与截止预算，同时检查当前定位健康。

## 优化状态的时间语义

关键帧、滑窗或回环算法输出的“最新优化状态”不一定对应当前输入。Adapter 必须把算法内部关键帧索引映射回原始观测时间，只在出现新的优化状态时发布一次；不得用当前输入时间或发布时间给旧关键帧重新盖章。需要与里程计、IMU 或其他状态配对时，也应按该关键帧的真实时间查询历史样本。用非等速输入回归验证索引、时间和状态对应关系，避免当前时刻的辅助状态与旧视觉位姿组成物理上不存在的联合状态。

若算法另有官方高频传播状态，迁移该输出而不是对低频优化状态重复盖章或插值伪造实时性。分别验证低频校正的正确性、高频传播的连续性，以及二者进入 canonical 状态组合后的唯一发布权。

随机采样会影响学习式前端和回环图的精度、延迟及复验稳定性。检查上游正式评测入口是否固定随机种子或覆盖运行参数；若有，应通过 Adapter 参数显式复用并记录到证据清单，不能依赖进程默认随机状态。输出覆盖率应在算法边界用处理诊断中的原始输入时间戳核对；独立高带宽订阅器漏帧只说明观察器过载，不能直接判定算法未消费输入。

## 有限观测 Action 与 AS2 Module

Action 调用下游 Service 时，客户端取消/超时只终止当前观测会话，不证明下游调用
已结束。保留真实 outstanding future 的占用，收到回复后先核对会话世代，再处理
原始采样时间；旧回复只排空，不能用于后续 Goal。真实 DDS 回归至少覆盖取消后
立即新建 Goal、旧回复迟到、单会话互斥、陈旧/未来观测和 ROS 时钟倒退。
若不支持强制终止下游请求，永久无回复时保持占用并明确重启恢复策略。

AS2 `ModuleBase` 在当前锁定版本要求实现抽象 `__call__`；仅提供命名方法不足以
构造 Module。安装模块文件到 ament share 的 modules 目录，并通过真实
DroneInterface `load_module()` 验证加载、调用和销毁。`destroy()` 应可重复调用：
DroneInterface.shutdown 会销毁已加载模块，不应在探针中先重复销毁 ActionClient。
YOPO-Tracker 静态 AirSim/CUDA 观测曾业务断言通过但清理失败，修正幂等销毁后
完整地面复验通过；该证据不包含移动目标身份、精度或导航闭环。

观测状态不能只在一个 timer tick 暴露成功标志，否则异步 Action 消费者可能仅收到
外推帧而漏掉所有成功观测。反馈保留最近观测关联状态、采样 ID 和有效期；
缺测/失效转换单独定义。验收按不同 capture ID/原始 stamp 计数，不能按重复反馈
数量判定观测覆盖。该问题已由真实 DDS 回归先失败后通过，YOPO-Tracker 最终静态 AirSim/CUDA
独立采样验收也已复验通过；移动目标与故障仍需各自验证。


## 文本查询替换固定类别接口

公共请求字段更名时同时更新 Service、Action Goal、Python Module、CLI、部署例子和
在仓库内的调用方；输出模型标签保留自身语义。公共 query 与实际 label/phrase 分开
记录，固定类别使用部署支持列表精确解析，开放词表不能按 query==phrase 再过滤。
后端选择由部署配置负责；独立 backend adapter 收束请求构造、查询规范化和模型
输出校验，避免将分割 mask 约束套到 boxes-only 模型。检查模型版本及 worker 世代，
替换模型后要求显式重启并失效旧会话。

字段更名和嵌套消息扩展都需重生成全部受影响消费者，避免只构建 Engine 而加载旧
Tool/Tracking 类型。Detect query 已在固定 onboard v0.1.1 外部 overlay 连同 AS2 Python
API 构建并通过实际 DDS；该镜像有 AS2 消息不代表已安装 Python API，运行前需实际
导入并加载其锁定局部 Python 依赖。公共 capture 的新鲜度用配置时钟下的源 stamp
与接纳时间/水位核查，接收发生在调用后并不排除排队的旧图；拒绝未来图时不推进
水位，以免一个错误源 stamp 阻塞后续正常图。回滚时重置水位并失效在途世代。

## ROS 1 基线与迁移完成条件

ROS 1 原实现可在隔离环境中用于迁移前数值对照，但对照环境不得被活动 Dockerfile、Compose、launch 或验收入口启动。基线输入、源码提交、参数和输出需可追溯；无法运行基线时如实记录，不以保留 ROS 1 runtime 代替迁移。

迁移完成至少证明：Humble 环境可从锁定源码构建；运行图没有 roscore、roslaunch、catkin devel space、ROS 1 Proxy 或桥；真实 ROS 2 输入由算法消费；活动输出和多机 peer 通信保持车辆身份、时间、坐标与失败语义；镜像内检查不存在 ROS 1 runtime。多机算法还要复用项目多机基础设施，验证每机命名空间、输入隔离和原生 peer 通信。
