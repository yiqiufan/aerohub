# AS2接入案例

以下保留原记录对应阶段的验证边界，不作为所有控制器、executor或项目的默认实现。通用职责、接口核对与调度方法在主Skill。

## 停止契约

RACER 的固定 AS2/PID 接口回归已复现枚举误判并验证兼容修复及拒绝路径；该回归的平台状态为合成输入。后续 AirSim/PX4 单机两段局部规划仿真闭环又验证了同一契约：两段曲线实际激活后，Action取消、停止服务成功、请求后POSITION反馈共同确认停止，再由原生Land及飞控landed/disarmed收口。这只覆盖该固定插件和短航段，不证明其他控制器、多机或完整探索通过，也不以协议确认代替物理稳定性验收。物理速度、漂移或稳定时间门限沿用项目实际验收需要，不因接口兼容修复默认增加；确需调整时记录原要求、实测依据和适用范围。

## 忙时反馈

该方法已在锁定 Humble/RACER 的隔离真实节点回归中复现旧版失败、新版通过，并完成双机 PC 地面复验；合成执行确认不代表 AS2 运动执行，多机飞行、板端及其他 executor 尚未验证。参见 RACER [隔离回归入口](../../../deployment/airsim/demos/racer_multi_ground/diagnostics/run_regression.py)与[验证记录](../../../deployment/airsim/demos/racer_multi_ground/validation.md)；纯异步或不同调度模型的项目先测量，不要求套用同一队列实现。

## 数值限制

RACER曾出现算法逐轴速度软代价与Adapter向量范数校验不一致。该案例支持追踪参数实际消费代码，不能规定其他算法使用同一速度或放宽执行限制。
