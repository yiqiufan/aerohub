# 双机原生完整探索模式

状态：隔离 ROS 无运动联调、真实地面就绪及两轮同配置完整探索飞行已完成。两轮自然结束、停止降落与清理通过；第二轮辅助记录读回不完整，整体仍为 partial。当前交付见 [PC 双机验收](PC_DUAL.md)。该历史版本、完整配置与分项证据见 [FOREST_COMPLETE.md](FOREST_COMPLETE.md)。原 `explore` 模式仍按原时长与终点位移判据运行，已有基线记录不变。

## 模式与输入

完整模式名为 `explore-complete`，通过既有 `full_flow.py --local <local.json> --mode explore-complete` 进入。**该命令会启动实际飞行流程。** 本地配置必须显式提供有限、正数 `completion_wall_budget_s`；没有默认时间，不从短程的 20 秒推导。整轮入口在启动服务之前验证该值。

空间范围继续来自所选源码的 fleet/flight 配置，不因模式改变自动扩展。仓库默认仍为原短程范围；使用已验证扩大范围前，必须对齐两份配置及对应源码/安装版本，不能把默认配置冒充扩大范围。源码与构建守卫仍生效，不改锁文件使错误版本通过。

预算从各机发布探索触发时按单调墙钟计时，覆盖首条轨迹等待与后续探索。原生 IDLE 的等待使用仿真时间，预算需要考虑仿真速度、探索与返回所需时间；预算只作兜底，不是探索完成条件。停止与降落继续使用原有独立预算。

## 判定与收尾

- `No grid`、无可访问前沿、IDLE 和重新分配都不直接结束任务。
- 监督器解析锁定原生节点日志，公布进程会话、触发代数、原生停止原因和结束来源。只接受本轮触发后、同会话的 `return finished` 请求、普通 STOPPED 确认和 FINISH 转换组合。初始无前沿、人工停止、未知结束或 ATSP 服务失败不能伪装成自然完成。
- 两机的新鲜自然结束状态均到达后，锁存全队结束证据，再各自停止、Land 和确认 landed/disarmed。锁存避免第一架开始正常收尾后，第二架丢失刚刚成立的全队结束条件。
- 超时标为 `budget_exhausted`，取消标为 `cancelled`，其他执行异常标为 `execution_failed`。这些情况仍尝试原有恢复流程，安全落地不会把探索完成改成 true。
- 完整模式使用探索触发后整段真实水平运动的最大离起点距离，沿用原运动距离数值，不要求返回后的终点远离起点。离线验收从实际位置事件重新计算，不把起飞算成探索。原短程模式仍使用原终点判据。
- `native_finished` 证明原生流程结束，不证明全部体素或整个 ForestScene 已覆盖。原生算法的返回判断、搜索/分配逻辑、等待常量、控制门限均未修改。

## 无运动验证

在本目录运行 `python -B -m unittest -v test_completion test_full_flow test_evaluate_cleanup`。新用例通过 AST 装载实际任务类，避开模块级 ROS 初始化和运动入口，验证真实 Python 方法与合成输入；不是实际 ROS 链路验证。

检查覆盖双机不同步结束、旧会话/旧触发、初始无目标、暂时空闲、人工停止、停止确认缺失、求解失败、超时、正常恢复和返回起点后的运动证据。另用已有两轮扩大范围日志回放监督解析，并只读重算旧短程验收；不会写回旧结果。

监督解析依赖锁定 C++ 日志格式；上游格式改变或缺少新监督字段时，完整模式拒绝成功，不推测终态。当前改动都是 Python 任务/监督层，无 C++ ABI 改动，但实际运行仍须加载匹配原生构建及当前 Python 源码。本版本两轮已验证配置范围内的原生返回和完整模式飞行，但不代表长期可靠性。

历史推进顺序为隔离 ROS 监督发布/任务订阅/停止接口、真实地面就绪，再到完整探索飞行；结果及未覆盖项由当前版本摘要分别记录。辅助记录缺项独立保留，不改写任务自然结束证据。

## 选择独立运行配置

local.json 可指定 `fleet_config`、`flight_config`；相对路径以 local.json 所在目录为准。不提供时保持原默认文件。两份规划 box 必须一致，启动前核对文件未变；运行记录包含所选配置来源和哈希。完整探索预算仍由 `completion_wall_budget_s` 显式提供，不写入公共默认值。
